```sh

dart test core && dart test cli
```

## Conventions

- **Places.** A service is a Squadron service in `core/lib/src/services/`. It
  runs in an isolate, a Web Worker{{#process_place}}, or the CLI's `serve` mode
  in another process (`P0G_PROCESS_ENDPOINT`){{/process_place}}; `app/lib/places.dart`
  picks the place, and each place reports its own facts.
- **Strategies.** An `Objective` holds ordered strategies; the first whose
  `available(facts)` accepts the place's facts runs. Never decide with
  `kIsWeb` or `Platform`: WebUI says web, AERA says Linux, and neither says
  root. Host-versus-device choices are strategies of one objective.
- **Device writes.** A `WriteStrategy` plans first (no side effects), the UI or
  CLI shows the steps and makes a `Confirmation`, then `Objective.apply`
  writes and returns a `Receipt`.
- **Logging.** `package:logging`. Every objective run logs a `StrategyRun`
  (objective, strategy, place, facts, outcome, time) on `objective.<name>`.
  The CLI prints records to stderr (`-v`, `--json`); the app shows them.
- **Adding code.** `mason make service` and `mason make strategy` from this
  folder; they insert themselves at the `// p0g:` markers.
{{#rust}}- **Rust.** `flutter_rust_bridge_codegen generate` writes bindings to
  `core/lib/src/rust/`. Bindings are sync (`default_dart_async: false`):
  Squadron owns threads, so a call runs inside whichever worker makes it.
{{/rust}}
